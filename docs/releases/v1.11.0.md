Large-file reading and rendering improvements since v1.10.0. The fmap backend,
which was proposed future work in v1.10.0, is now built in and always enabled.

## Data loading and memory

- Add the C/WebAssembly fmap backend for on-demand file reads, bounded per-file
  resident page caches, page eviction, and reuse of overlapping reads.
- Support all nine ENVI scalar numeric types across BSQ, BIL, and BIP layouts
  in either byte order. Preserve numeric precision in raster reads and reject
  truncated payloads or dimensions outside exact file-offset arithmetic.
- Add fmap-backed TIFF range and block reads for supported uncompressed,
  PackBits, LZW, and Deflate paths, including integer and floating-point
  predictors. Retain compatible decoding paths for other supported TIFF cases.
- Improve multipage and pyramid TIFF indexing, native overview selection,
  per-band level associations, and reads beyond 4 GiB.
- Bound read/decode admission and result buffers; prioritize visible work and
  cancel obsolete reads after view, band, or dataset changes. Move page-fill
  admission, overlap deduplication, and lease ownership into the C/WASM core.

## Rendering and controls

- Move pyramid composition and RGB coloring into display workers where
  supported, with a local fallback when worker rendering is unavailable.
- Retain incremental composition results and update changed regions to reduce
  repeated rendering work. Preserve reads still needed by another visible panel.
- Correct toolbar button padding and icon centering.
- Match scale-bar and color-composite text size to dataset titles.
- Collapse the band dock to the color-composite label and mode button in color
  mode; restore the band selector in grayscale mode and remove the lock icon.

## Build and validation

- Pin the fmap C/WASM build toolchain and verify the generated artifact against
  its source manifest.
- Add GitVersion calculation shared by local commands and CI, using
  `+semver:` commit-body annotations. Release titles remain version-only.
- Run validation suites in parallel, then build and test the packaged HTML
  offline before retaining it as the distribution artifact.
- Update Tailwind CSS to v4 and related build/test dependencies. The CSS build
  requires Safari 16.4+, Chrome 111+, or Firefox 128+; these are compatibility
  requirements, not a claim that every browser was validated for this release.

Release-commit CI passed: 527 unit tests, 41 desktop Chromium browser tests,
four opt-in large-file tests, C/WASM ABI checks, checked browser/queue
benchmarks, lint, and offline single-file package verification.
[Validation run](https://github.com/chemimage/not-envi/actions/runs/43266932608).
The published HTML and Pages deployment were verified to match the tested
distribution by SHA-256.

## Known limitations

- [RGB export still saves one band instead of all three channels (#28)](https://github.com/chemimage/not-envi/issues/28).
- [Export progress UI remains pending (#1)](https://github.com/chemimage/not-envi/issues/1).
- Cache limits are per file/component; a
  [shared application-wide memory budget remains pending (#33)](https://github.com/chemimage/not-envi/issues/33).
